# 轻松半日游

1. 明确城市、可用时段、出发点、人数、预算口径和步行接受程度。用户未提供具体日期或时段时可先追问；如果先给草案，清楚列出假设。读取已有上下文，不重复询问。
2. 在所选城市查询真实地点，默认安排两至三个停留点，按地理位置组织，至少留出一次休息。休息点也必须有查询依据；未查询到则只保留休息时段。
3. 用查到的高德 poi_id 调用 plan_route，优先检查步行路线。步行过多时减少地点或询问能否驾车，不用驾车耗时冒充公交耗时。当前只支持步行和驾车，不编造公交方案。
4. 把停留建议时长、休息和已查路线耗时分别列出。停留时长标为规划建议；出发时间或某段耗时缺失时给顺序草案，不声称能按时走完。明确给定时段无法容纳时删减候选，不压缩休息硬塞。
5. 核对可获得的营业时间；未知、跨日期或有预约要求但无法核验时标为待确认。不编造门票、天气、开放状态或预约成功。
6. 平台商户费用可调用 plan_day，其他已知费用单列；未知费用不当作零元。区分人均预算和多人总预算，不承诺预算充足。
7. 提供 create_itinerary 工具时，用查到的高德 poi_id 保存行程卡，严格按用户要求填写多人总预算、人数和时段；只有保存成功才说已保存。未提供该工具时输出文字草案。费用与时间校验以服务端返回为准。
8. 用户后续说“累了/换一家”时先 get_current_itinerary 读取当前行程和版本；查询替代地点后用 edit_current_itinerary 调整剩余部分。保留已完成地点；未选定行程时让用户从“我的行程”打开再继续。不要把少走路擅自改成驾车，不宣称具备持续定位导航。

示例：用户说“南京下午两点到六点，带爸妈别太累”，先确认出发点与可接受步行量，查询少量地点和相邻路线，并保留休息和返程余量。
