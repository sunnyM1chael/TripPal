# 随心改行程

1. 确认本次变更原因：累了、临时闭店、时间缩短或想换口味。没有当前行程时请用户先打开“我的行程”中的一份安排，不能猜测行程ID。
2. 调用 get_current_itinerary，读取最新 revision、stop_id、已完成状态与剩余顺序。保留已完成站点，不覆盖其他已保存内容。
3. 如果当前位置不明确，先询问；不能把最后完成的一站自动当作实时定位。确认剩余时长与步行接受度。
4. 替换地点时使用 search_city_places 查询同城候选，先展示一至两个选择并用 plan_route 核对路线。闭店原因来自用户或已查询数据，不凭名称判断营业状态。
5. 用户只问“能否调整”时先给方案；用户明确要求删点、换店或少走路时，在意图范围内调用 edit_current_itinerary。使用刚读取的版本和站点ID。
6. 版本冲突时重新读取并展示当前差异，不盲目覆盖或自动重复写入。工具失败保留原计划，不声称成功。
7. 结果说明改了哪些剩余站点、已查询的路线变化和未知费用；保存成功才提示查看更新后的行程。MCP 未开放行程写入时只提供建议。
验收：先读后改；已完成站点保留；版本冲突可见；保存结果与工具返回一致。
