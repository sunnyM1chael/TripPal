# 预算一日游

1. 确认城市、出发点、可用时间、人数，以及预算是人均还是全团。本次要求优先，不重复询问已有信息。
2. 用 search_city_places 查询真实地点，按相近区域选择两至三个主要停留点。不要猜门票、公交线路或景点免费政策。
3. 平台餐馆先 shop_detail，再用 compare_shops 对比明确的 shop_id；多人平台餐费用 plan_day 核算。高德 poi_id 不能作为平台商户ID。
4. 用 plan_route 查询相邻地点的步行或驾车耗时，交通方式遵循用户意愿。计入停留与休息时间，超时则删减地点。
5. 输出费用表：项目、计价人数、已知单价、小计、未知项。交通、门票和未查到的餐费标为待确认。不能用已知小计保证总预算足够，也不能默认优惠券抵扣。
6. 给出一个主方案和一个省钱替换思路，逐项说明依据。用户要求保存时用 create_itinerary，只有成功后才说已保存；否则是文字草案。
验收：每个地点有来源；预算口径一致；未知费用可见；路线与时间有查询依据。
