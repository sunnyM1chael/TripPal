# 驴友：多日行程规划

在驴友首页选择“多日行程规划”，或直接说：

> 常州3天，两个人，全程总预算1500元，喜欢园林和小吃，驾车，不想太累。10月30日开始，每天9点到18点，请生成并保存行程。

## 规划范围

- 一个城市、1至7天，多日每天1至4个地点；旧单日行程仍支持最多6站。
- 步行或驾车。跨城交通、公交班次、天气、酒店预订、门票预约尚未接入。
- 预算是所有人所有天的总额。助手先确认口径，不把人均预算直接当全程总预算。
- 出发日期可留空，显示第几天；当前所有天共用每日起止时段及每日休息时长，首末日特殊抵离时段需单独核实。
- 先按真实地点的地址和区域分天，再用高德查询相邻站点之间的路线。没有采用全局最短路或营业时间优化算法，不声称“最优路线”。

## 实际执行

Skill `plan-city-trip` 按需加载：补齐需求 → 批量搜索高德候选 → 按天分配地点 → `create_itinerary` → 服务端重新核对POI、城市和路线 → 保存并展示每天安排。

`search_trip_places` 最多6个关键词，每词最多5个结果，并发查询上限3。服务端重新核对地点并计算路线；生成行程时复用刚查到的坐标，避免逐段重复读取POI。路线查询阶段最多45秒，保留成功结果，未完成段落显示未知；地点核验失败则不保存不可靠行程。

每天独立核算：停留 + 额外休息 + 已知路线耗时。某天超时，不能被另一天天数的空闲时间抵消。每日建议钟点从起始时间递推，休息放在当天首站之后；某段路线失败，后续钟点停止推算。每天首站前接驳和末站返程不包含在已计算路线中。

展示多人已知参考消费小计与未知项。高德参考消费不是完整票价或实时套餐报价，住宿、交通、门票和预约费用不能补猜；即便已知小计低于预算，也不保证全程预算足够。

## 保存与调整

复用原来的 `itineraries.document` JSON，不新增表。已启用行程保存的数据库无需新增迁移；尚未初始化行程表的环境仍需按原流程初始化。

新增 `day_count`、`start_date`、`preferences`、每站 `day`、按天汇总与建议钟点。旧记录缺少这些字段时按单日处理，可继续编辑。

“我的行程”展示每天概览，聊天卡展示分天地点及高德路线入口。替换地点保留原天序，上移和下移只在当天内生效；不能删空一天，已完成站点仍锁定。修改不同天数或跨天重组目前需要重新生成一份方案，原行程不会被静默覆盖。

MCP 自动发现该场景的 Prompt/Resource，但依旧没有行程写入权限；外部客户端只能按已开放工具提供建议，不能假称保存。

## 验证边界

自动化覆盖日期跨月、预算、逐日时间窗口、无跨夜路线、失败段后续时间未知、跨天编辑拦截、旧记录编辑、技能加载与工具循环，以及模拟高德HTTP协议。真实模型效果、高德配额/可达性和浏览器交互需在本机服务上单独验收。
