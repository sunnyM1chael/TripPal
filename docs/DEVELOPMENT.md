# 固定开发入口与验收

## 目录约定

`F:\Projoct-code\旅伴` 是后续修改、提交和拉取更新的主仓库。Java/Vue 源码在 `hmdp-plus`，Python 在 `travel-agent`；不要把不同根目录结构的分支直接合并到旧项目。

当前已配置好的旧 Java `F:\Projoct-code\hmdp-plus-master` 可继续作为兼容运行副本。IDEA 启动配置必须明确指向这一份或主仓库中的 Java，两者只启动一个，端口默认8085。旧副本不是新的开发源；有 Java 改动时须先同步对应代码和规则，保留它的本地连接配置。本轮行程功能只修改 Python/Vue，不需要再次同步 Java。

统一从主仓库根目录启动，在两个 PowerShell 窗口分别运行：

```powershell
.\dev.ps1 agent
.\dev.ps1 web
```

脚本固定 Python/Vue 的目录，Python 使用 `--no-sync` 保留可选驱动。Java 在 IDEA 启动。不会自动停止现有进程、修改密码、安装依赖或启动 Docker。

当新增 Java 偏好接口需要同步时，可执行 `./dev.ps1 sync-java`；这只是偏好模块的兼容同步，不是通用全仓库更新工具。彻底停用旧副本前，需要在 IDEA 迁移其启动环境变量、核对连接设置，并验收主仓库 Java；不要直接覆盖配置文件。

## 启用保存行程

MySQL 用户需在主仓库根目录执行一次非破坏性的建表升级：

```powershell
.\dev.ps1 migrate
```

它执行 `CREATE TABLE IF NOT EXISTS itineraries` 并记录 schema version 2，不修改已有聊天或 Java 业务表。升级后刷新页面即可，运行中的 Python 每隔至少5秒按需重新检测行程表。如果刚更新了 Python 代码，需先重启 Python 加载新代码。运行账户无建表权限时，用初始化账户执行同一 SQL，再恢复运行账户。SQLite 开发环境启动自动新增行程表。

未升级的 MySQL 不会导致原聊天启动失败；行程工具暂不提供，行程页面会说明升级命令。如果连接数据库本身失败，仍会按原规则启动失败，不静默回退 SQLite。

## 真实服务检查

主仓库根目录执行 `./dev.ps1 check`，或在 `travel-agent` 执行：

```powershell
.\.venv\Scripts\python.exe scripts\check-stack.py --live-maps
```

检查 Agent 健康、Java 分类、访客记忆接口、行程表及真实高德城市查询。默认不调用模型，不修改数据库；会有一次正常访客 Cookie 初始化。需要核验登录偏好时，在本机终端设置 `TRAVEL_CHECK_TOKEN` 为有效登录令牌，检查后移除该环境变量，不要发送令牌或写入 Git。未设置令牌明确显示 SKIP，不代表登录链路已验证。

SQL 和脚本验证不能代替界面验收，按下面顺序完成：

1. 在“我的记忆”保存城市、预算和忌口，刷新和重新登录后检查归属。
2. 在“我的行程”新建，选城市、两至三个准确地点、人数和多人总预算，保存后刷新。
3. 换店、删除地点、上移/下移，确认相邻路线和时间小计更新。
4. 标记第一站完成，再调整后续地点，确认第一站保持原样；不能越序完成或将未完成地点移到已完成区。
5. 同一行程开两个页面，同时修改；旧版本应提示冲突并重新加载，不能覆盖另一页修改。
6. 从行程进入“让旅伴调整”，说“第二站换成咖啡馆”；查看查询依据和保存后的最新行程。
7. 重启 Python，确认聊天与行程都能恢复。切换身份后不能看到另一身份的行程。

路线均为查询时参考，持续定位、语音和实时重算由高德承接。没有查到耗时的路线必须显示未知，不能算成零分钟；费用只展示已知参考小计，包含未知费用时不承诺总预算充足。
# Java 本机配置与 Git

`hmdp-core-service/src/main/resources/application.yml` 和 `shardingsphere.yaml`
含本机连接信息，现已停止 Git 跟踪；已有本地文件继续使用，不要覆盖。
首次克隆时，将同目录的 `application.example.yml`、`shardingsphere.example.yaml`
分别复制为上述文件，在本地填写 Redis 和两个 MySQL 数据源的密码。
示例保留业务配置及分片规则，包括吃玩工坊四张表固定路由至 ds_0。
后续修改分片规则时，同时更新无密码的示例文件和本机配置。

Git 忽略规则不能清除历史提交中的旧配置。历史凭据需要由配置所有者轮换；
不要将本机生成的 JAR、source JAR 或诊断日志上传，它们可能包含本地配置。
